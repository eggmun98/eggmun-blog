# 블로그 작성 가이드

이 문서는 이 프로젝트에서 새 글을 작성하거나 기존 글을 수정할 때 참고하는 운영 가이드다.

## 1. 글 파일 위치

모든 글은 아래 폴더에 Markdown 파일로 저장한다.

```text
content/posts/
```

예시:

```text
content/posts/ai-era-frameworks.md
```

파일명은 곧 `slug`가 된다.  
즉 `content/posts/my-first-post.md`로 만들면 주소는 `/blog/my-first-post`가 된다.

## 2. 글 파일 기본 형식

새 글은 아래 형식으로 시작한다.

```md
---
title: "글 제목"
excerpt: "목록, 검색, SEO 설명에 사용할 짧은 요약"
date: "2026-07-31"
image: "/images/example-thumbnail.png"
tags: ["태그1", "태그2", "태그3"]
---

# 글 제목

## 1. 들어가며
본문을 작성한다.
```

## 3. frontmatter 설명

- `title`: 글 제목
- `excerpt`: 글 카드, 검색 결과, 메타 설명에 노출되는 짧은 소개
- `date`: 발행일. `YYYY-MM-DD` 형식 사용
- `image`: 썸네일 경로. `public/images/...` 아래 파일을 기준으로 `/images/...` 형식 사용
- `tags`: 글에 붙일 태그 배열

중요:

- `excerpt`는 목록 카드와 SEO에 바로 사용된다.
- `image`가 잘못되면 썸네일과 Open Graph 이미지가 깨질 수 있다.

## 4. 썸네일 이미지 넣는 방법

썸네일 이미지는 아래 폴더에 넣는다.

```text
public/images/
```

예시:

```text
public/images/frameworks-thumbnail-refined.png
```

frontmatter에는 이렇게 적는다.

```md
image: "/images/frameworks-thumbnail-refined.png"
```

## 5. 제목 작성 규칙

본문 제목은 아래처럼 쓰는 것을 권장한다.

```md
# 글 전체 제목

## 1. 들어가며
## 2. 본론 제목
## 3. 본론 제목
## 4. 마치며
```

현재 프로젝트 렌더러 기준:

- `h2`는 위쪽 여백이 크게 들어간다.
- `h3`도 일반 문단보다 더 넓은 간격으로 보이도록 설정되어 있다.

즉 큰 장은 `##`, 그 안의 시나리오나 하위 주제는 `###`로 쓰는 편이 가장 보기 좋다.

## 6. 자주 쓰는 마크다운 문법

### 강조

```md
**중요한 문장**
```

예시:

```md
**프레임워크란 무엇일까?**
```

### 기울임

```md
*기울임 텍스트*
```

### 인용문

```md
> 인용문입니다.
```

강조와 함께 쓸 수도 있다.

```md
> **AI 시대에도 프레임워크는 필요할까?**
```

### 구분선

```md
---
```

문단 사이 흐름을 끊거나, 큰 전환을 줄 때 사용한다.

### 순서 없는 리스트

```md
- 첫 번째
- 두 번째
- 세 번째
```

### 순서 있는 리스트

```md
1. 첫 번째
2. 두 번째
3. 세 번째
```

### 코드 블록

언어를 붙여서 작성한다.

```md
```ts
const message = "hello"
```
```

프로젝트에서 비교적 안전한 예시는 아래와 같다.

- `text`
- `ts`
- `tsx`
- `js`
- `jsx`
- `json`
- `bash`
- `css`

## 7. 이번에 실제로 겪은 마크다운 주의사항

### 1) 강조 뒤에 한글 조사가 바로 붙는 경우

아래 같은 패턴은 렌더링이 애매해질 수 있다.

```md
**문맥(Context)**을
**"어떻게 구현할 것인가"**를
```

이 프로젝트에서는 보정 로직이 들어가 있지만, 아래처럼 아예 강조 범위 안에 조사를 넣는 방식이 더 안전하다.

```md
**문맥(Context)을**
**"어떻게 구현할 것인가"를**
```

### 2) 글에서 줄을 띄우고 싶을 때

Markdown은 엔터 한 번만 쳐서는 문단이 나뉘지 않을 수 있다.

문단을 확실히 나누려면 빈 줄을 한 줄 더 넣는다.

```md
첫 번째 문단

두 번째 문단
```

강제로 줄바꿈만 하고 싶다면 `<br />`를 쓸 수 있지만, 일반 글쓰기에서는 문단 분리를 우선하는 편이 좋다.

### 3) 큰 주제 간격이 좁아 보일 때

문단 엔터로 해결하려 하지 말고, 제목 레벨을 맞게 사용한다.

- 큰 장 제목: `##`
- 그 안의 하위 제목: `###`

현재 프로젝트에서는 제목 레벨별 여백이 컴포넌트에서 관리된다.

관련 파일:

```text
components/markdown-content.tsx
```

## 8. 새 글 작성 순서

1. `content/posts/` 아래에 새 Markdown 파일 생성
2. frontmatter 입력
3. `#` 제목과 `##` 장 제목 구조 작성
4. 썸네일 이미지를 `public/images/`에 추가
5. `image` 경로 연결
6. `excerpt`를 카드용 한두 문장으로 정리
7. 개발 서버에서 미리보기 확인

## 9. 수정할 때 함께 보면 좋은 파일

- `content/posts/`: 실제 글 원본
- `public/images/`: 썸네일 이미지
- `components/markdown-content.tsx`: 제목 간격, 인용문, 코드 블록 등 렌더링 스타일
- `lib/posts.ts`: Markdown 파일을 읽는 로직
- `app/blog/[slug]/page.tsx`: 글 상세 페이지 렌더링

## 10. 확인 방법

개발 서버 실행:

```bash
npm run dev
```

브라우저에서 글 페이지 확인:

```text
http://localhost:3000/blog/슬러그
```

포인트:

- 강조 표시가 `**별표**` 그대로 보이지 않는지
- 인용문이 왼쪽 보더와 함께 잘 보이는지
- `##`, `###` 제목 간격이 의도대로 보이는지
- 썸네일이 깨지지 않는지
- excerpt가 너무 길지 않은지

## 11. 추천 작성 습관

- `excerpt`는 본문 첫 문장을 그대로 복붙하지 말고 카드용으로 따로 다듬는다.
- 큰 흐름 전환이 있을 때만 `---`를 사용한다.
- 강조는 정말 중요한 문장에만 쓴다.
- 하위 제목 없이 짧은 문단만 길게 이어지면 가독성이 떨어진다.
- 글을 다 쓴 뒤에는 반드시 한 번 렌더링 화면에서 읽어본다.
